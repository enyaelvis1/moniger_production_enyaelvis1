# Release v0.1.0-rc.4

## Title

OWASP Security Hardening And Release Guardrails

## Description

This release candidate promotes the latest OWASP-aligned security work from `develop` into a release-ready branch for validation before production rollout. It closes the key security findings from the 2026-05-21 review and adds guardrails so future releases fail fast when critical app-link configuration is missing.

## Included Changes

- removed unsafe `Origin` header fallback for password reset, invite, billing, and subscription callback links
- made `APP_BASE_URL` mandatory for security-sensitive server-generated links
- scrubbed password reset tokens from the browser URL after session setup
- reduced public subscription confirmation exposure for signed-out visitors
- added browser security headers through Vercel configuration
- moved Supabase auth session persistence from `localStorage` to per-tab `sessionStorage`
- added a release verification command for `APP_BASE_URL`
- added targeted regression tests for:
  - auth storage behavior
  - reset-token URL scrubbing
  - signed-out public subscription confirmation behavior

## Verification

The following checks passed on the integrated branch before this release branch was created:

- `npm run test -- src/integrations/supabase/auth-storage.test.ts src/pages/ResetPassword.test.tsx src/pages/PricingConfirmed.test.tsx`
- `npm run verify:release:security`
- `npm run build`

## Known Notes

- this is still a release candidate, not a final live-billing cutover
- Paystack live-key verification remains dependent on external Paystack account approval
- broader security regression coverage can still grow over time, but the major OWASP review items are now addressed
